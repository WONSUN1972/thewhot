THE WHOT · 카페24 적용 절차

2026.11.02 · 로컬 디자인 + 카페24 회원·결제 백엔드

현재 단계: 브랜드 화면 검토 및 적용 준비.
자료 수집·스마트디자인용 변환·로컬 검수는 완료. 실제 카페24 업로드와 회원·결제 연결은 미진행.

로컬 메인 보기 · 상품 소개 보기

1. 로컬 화면 검토

현재 준비: 브랜드 13페이지와 협업 게시글 1개. 메인, ABOUT, PRODUCT, PARTNERSHIP, NEWS, CONTACT를 확인한다. 기존 이미지에 문구가 포함되어 모바일에서 작게 보이는 부분은 별도 재편집 대상으로 기록한다. 현재 미리보기에는 실제 장바구니·주문·로그인 화면이 구현되어 있지 않다.

완료 기준: 브랜드 구성·디자인 수정 목록 확정.

2. 카페24 작업용 스킨 준비

쇼핑몰 관리자에서 사용할 스마트디자인 스킨을 선택하고 복사본을 만든다. 스킨 번호, PC/모바일 분리 여부, 반응형 여부, 레이아웃 경로를 기록한다. 현재 운영 화면은 유지하고 미리보기 스킨에서 작업한다.

필요 정보: 쇼핑몰 ID, 관리자 접근, 작업 스킨 번호. 계정 비밀번호를 문서에 기록하지 않는다.

3. 이미지 업로드

THE_WHOT_카페24_이미지업로드.zip을 압축 해제한다. 관리자 디자인의 파일 업로더에서 web/upload/thewhot/images 폴더 구조를 맞춘다. 업로드 결과가 /web/upload/thewhot/images/파일명으로 열리는지 확인한다. 스킨 파일과 이미지 파일은 서로 다른 위치에 넣는다.

완료 기준: 사용 이미지 132개 경로 확인. 파일명과 대소문자 유지.

4. 브랜드 페이지 적용

THE_WHOT_카페24_스마트디자인.zip은 스킨 자동설치 ZIP이 아닌 개별 파일 배치용이다. /brand/*.html과 /css/whot-brand.css를 작업 스킨에 추가한다. 각 페이지의 @layout 경로를 실제 스킨에 맞춘다. index.html은 작업본에만 적용한다. navigation/footer 조각은 기존 레이아웃에 수동 연결하며, 브랜드 페이지의 폭·여백과 모바일 헤더를 조정한다.

완료 기준: 기존 메뉴 순서 유지, 모든 내부 링크·이미지·Vimeo 재생 확인. route-map.json 참조.

5. 상품·회원·주문 모듈 연결

카페24에서 실제 상품명·가격·옵션·재고·판매 방식을 등록한 뒤 product-mapping-draft.json에 상품번호를 기록한다. 기존 PRODUCT 소개에서 카페24 상품 상세로 연결한다. 로그인·장바구니·주문서·마이페이지는 선택 스킨의 기본 모듈을 활용해 브랜드 디자인을 적용한다. 로컬 정적 파일로 결제·회원 기능을 흉내 내어 운영하지 않는다.

완료 기준: 카페24에서 로그인 → 상품 옵션 선택 → 장바구니 → 주문서 → 주문 조회가 이어짐. 독립 회원·결제 서버는 구축하지 않음.

6. 소셜 로그인·PG·운영 정책 설정

사업자 소유 카카오·네이버 계정으로 연동·심사를 진행한다. 최종 도메인의 리디렉션 설정을 확인한다. PG는 판매 품목을 기준으로 취급 가능 여부와 계약·심사를 확인한다. 배송비·픽업·취소·환불·성인인증을 확정한다. 문의 폼은 forms.json을 기준으로 카페24 게시판 또는 지원되는 폼에 연결한다. 기존 약관의 회사명 등 미완성 문구를 수정한다.

완료 기준: 소셜 제공자별 가입·재로그인·동의 취소 확인, PG 테스트 결제·취소·환불 확인. 사업자 본인 인증·계약 입력은 계정 소유자가 수행.

7. 카페24 작업본 통합 검수

PC·모바일에서 메뉴·브랜드 본문·상품 옵션·품절·주문·마이페이지·문의 접수를 검수한다. 결제 중 이탈·실패·취소·환불과 배송/픽업 분기를 확인한다. 로컬 검수는 카페24 모듈 검수를 대체하지 않는다. 원본 광고성 게시글 62개는 이관 제외 상태로 유지한다.

완료 기준: 주요 기능 오류 없음, 실제 접수·주문이 관리자에 기록됨. 테스트 거래는 시험 환경을 우선 사용하고 실거래는 정해진 금액·취소 절차를 확인 후 진행.

8. 도메인 전환과 오픈

작업본 검수 후 대표 스킨을 전환하고 www.thewhot.com 도메인을 연결한다. 기존 DNS를 기록하고 메일용 MX/TXT 레코드를 보존한다. 기존 URL과 신규 경로를 비교해 지원되는 리디렉션을 설정한다. SSL, 로그인 콜백, PG, Vimeo, 검색 노출을 재확인한다. 문제 발생 시 기존 DNS·대표 스킨으로 복구한다.

완료 기준: 최종 오픈 확인 후 전환. 현재는 도메인·DNS·운영 스킨을 변경하지 않음.
